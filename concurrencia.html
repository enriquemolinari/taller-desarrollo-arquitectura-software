¿Puedo como desarrollador desentenderme completamente total la BD se encarga de todo? ¿Tengo que escribir código de cierta forma para garantizar correctitud o simplemente delego en la BD y me desentiendo?

Concurrencia

Nunca puedo desentenderme!

Es una combinación entre la BD y la Aplicación que puede variar segun el caso de uso que quiero implementar.

Tipo 1: Dos Transacciones de lectura/escritura ingresan a la vez (Database-level Tx).
Tipo 2: Transacciones separadas de lectura/escritura (Application-level Tx).

La clave: ambas Tx leen el mismo dato antes de que alguna comitee.

Avanzar con las flechas: cada paso mueve el cursor "ahora". Ana y Beto ya vieron el mapa de butacas y eligieron la 1; acá se muestran sólo sus Tx de compra, que entran a la vez. Cada compra verifica que la butaca esté libre (SELECT) y hace un INSERT en la tabla pasaje, que no tiene constraint. Remarcar que B decide vender con un dato que, cuando A comitea, deja de ser cierto: por eso la butaca 1 queda vendida dos veces.

La clave: la compra no vuelve a leer la butaca, confía en el mapa que vio antes.

Avanzar con las flechas. Ana y Beto ven el mapa de butacas (Tx A y Tx B) y eligen la 1. A diferencia del caso 1, las compras NO entran a la vez: primero compra Ana (Tx A') y después Beto (Tx B'). Cada compra es un INSERT en la tabla pasaje, que no tiene constraint: por eso la butaca 1 queda vendida a Ana y a Beto. La clave está en el INSERT + COMMIT: ninguna de las dos Tx vuelve a leer cómo está la butaca, confían en el SELECT de antes del tiempo pensando. Al final se resaltan las 4 Tx de BD: ninguna es concurrente con otra. Lo que se solapa son las Application Level Tx de Ana y de Beto, que la BD no conoce.

Niveles de Aislamiento (ANSI SQL)

  1. Read Uncommited
  2. Read Commited
  3. Repeatable Read
  4. Serializable

¿Que Base de Datos estan usando? ¿Saben en que nivel de aislamiento esta ejecutándose?

Concurrencia

Isolation Levels (ANSI SQL)

PostgreSQL, Oracle y MS SQL Server por defecto usan Read Committed. MySQL y MariaDB en Repeatable Read.

Por defecto, las BDs relacionales estan configuradas relajando el aislamiento completo.

El aislamiento completo no permite ejecutar transacciones en forma concurrente. Ojo: Hablamos de MySQL con InnoDB, MyISAM no soporta Transacciones.

Concurrencia

Para controlar la concurrencia existen dos estratégias:

  • Pesimista: Prevenir que pueda darse, principalmente utilizando locks, tanto en forma explícita desde la aplicación o implícita cuando lo hace la Base de Datos segun el nivel de aislamiento.
  • Optimista: No lo prevenimos, pero lo detectamos luego y rollbackeamos. De forma explícita desde la aplicación versionando los objetos o en forma implícita la BD utilizando MVCC (snapshot isolation).
